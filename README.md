# Git 插件更新

在**设置 → 插件更新**一页里检查并更新从 GitHub / Git 安装的插件，并让升级过程看得见：四步进度条、每步耗时、实时日志、结果横幅。

## 它做什么

- 设置左侧导航新增独立一栏 **「插件更新」**（只在设置里，不动插件详情页和插件页）。
- 列出 profile 里从 `github:owner/repo`、`git+https://…`、`git@host:owner/repo` 安装的插件，每行显示：
  - 插件名、版本、仓库、跟踪分支（未写分支时是远端 HEAD）、是否已钉 commit；
  - 已装 commit → 上游最新 commit、GitHub 比较链接、上游最新 commit 的提交时间；
  - 状态徽标：**有更新 / 已是最新 / 无法检查（带原因）/ 待重启 / 更新中 / 未安装**。
- **列表下方简单列出非 Git 来源的插件**（registry / tarball / `link:`）：只显示名称、版本和来源类别，不检查也不更新。
- **点插件名直达详情页**：点击名称会关闭设置并打开 DSH 左侧「插件」面板里该插件的详情页；宿主没有插件页导航时名称保持普通文本，设置也不会被关掉。
- 每行有 **检查更新** 与 **更新到 `<sha>`**，页首有 **全部检查**；第一次打开会自动检查未检查/缓存过期的行。
- **检查不再阻塞页面**：每行独立检查（最多同时查 3 行），某一行查完就立刻可以更新，不用等其它行；检查期间其它行的操作照常。
- **多个插件可以同时更新**（默认最多 3 个）：每行有自己的四步进度、日志和「取消更新」，取消只停这一行。真正的 pnpm/卸载/安装由宿主 profile 写锁串行执行，所以同时点也不会把 profile 写坏。
- 点「更新」会先进入确认态（按钮变「确认更新到 …」，8 秒内再点才执行），确认框里显示的 commit 就是实际安装的 commit。
- 更新按 **检查上游 → 卸载原版本 → 安装目标版本 → 校验安装结果** 执行，页面是四步状态条（运行中/完成/失败 + 每步耗时）、整体耗时和可展开的实时日志（最近 8 条 / 共 N 条）。
- **更新时那一行不会消失**：卸载阶段插件会从宿主插件列表里消失，宿主用开跑前的快照把行补回来，页面继续显示进度；关掉设置再打开，步骤与结论仍在（任务在宿主里）。
- **日志不跨设置页保留**：关闭设置或切到别的设置页后，已完成任务的更新日志会被丢弃；重新打开时只看到进度与结果横幅，不再显示旧日志。正在运行的任务保留日志，重开设置仍能看到实时输出。
- 失败或取消会自动把原版本装回去；默认把依赖**钉到具体 commit**（`github:owner/repo#<sha>`），回滚精确。
- 更新成功后按宿主的结论提示「已生效」或「重启 DSH 后生效」；待重启标记会持久化，宿主真的重启并刷新页面后自动消失。
- 更新期间可以「取消更新」：只取消这一行正在跑的安装；如果已经卸载，则把旧版本装回。

## 它不做什么

- 不检查、不更新 registry 包、tarball、`link:` 本地克隆——它们只在列表下方简单列出来，没有检查/更新按钮。
- 不自己跑 `pnpm`：卸载、安装、回滚全部委托给宿主的插件管理器（`removeBundle` / `installBundle` / `cancelInstall`），失败原因原样转述。
- 不存凭据：探测只用本机 `git` 的配置与凭据（SSH key / credential helper），并且禁掉一切交互提示——不会弹窗向你要用户名或密码；两者都不通时只报「无法检查」。
- 不展示提交列表或文件变更（只显示 commit 与版本号）。
- 不能自己重启 DSH：页面只给「刷新页面」按钮和明确指引。
- **不更新本工具自己**：如果本工具本身以 Git 来源出现，那一行只给提示，请到插件页更新（否则宿主卸载它时，这一页和路由会一起消失）。

## 使用

1. 打开设置（侧边栏底部或快捷键）→ 左侧 **插件更新**。
2. 首次打开会自动检查；之后可点某行的「检查更新」或页首「全部检查」强制刷新。
3. 有更新时点「更新到 `<sha>`」，再点一次「确认更新到 `<sha>`」开始；过程中的步骤、耗时、日志都在行内。
4. 更新完成后：
   - 宿主说已生效：横幅显示「已更新到 `<sha>`，已生效」，可点「刷新页面」；
   - 宿主要求重启：横幅显示「已更新到 `<sha>`，重启 DSH 后生效」，给出 ① 保存工作 ② 退出并重新启动 DSH ③ 回来刷新页面 的指引；**只刷新页面不会加载新代码**。
5. 想改配置或看启用状态时，点插件名即可关闭设置并跳到它的详情页；关闭设置后，已完成任务的更新日志不再保留。

## 失败与回滚

| 情况 | 结果 |
| --- | --- |
| 上游探测失败（网络/超时/凭据） | 状态显示「无法检查」并给出原因，不改任何东西 |
| 卸载失败 | 报告 `REMOVE_FAILED`，不进入安装 |
| 安装失败 / 取消 | 把原版本装回去（优先钉回原 commit），报告失败原因；横幅写明「已回滚」 |
| 装完校验不过（commit 不符、包名不符、没有 `dsh.bundle.patch`） | 同样自动回滚，报告 `VERIFY_FAILED` |
| 回滚也失败 | 报告 `RESTORE_FAILED`，那一行保留并标「未安装」，提示到插件页重装 |

每次检查/更新的结论（含该仓库该走 HTTPS 还是 SSH 的 `transport`）记在 `<profile>/.git-updates/state.json`（0600，不含凭据）；「待重启」标记带宿主进程标识，重启后由启动对账自动清掉。

## 配置

写在 profile 的 `cordis.patch.yml` 里同一 id 的 config 覆盖即可：

```yaml
- id: git-updates
  name: dsh-git-updates
  config:
    pinCommits: true               # 更新后钉到具体 commit；false 则保持分支跟随
    sshFallback: true              # HTTPS 读不到时改用 SSH 再试
    probeTimeoutMs: 15000          # 单次 git ls-remote 超时
    cacheTtlMs: 600000             # 检查结果缓存时长
    maxConcurrentUpdates: 3        # 同时更新的插件数上限（1-8）
    trackedRefs:                   # 包名 → 跟踪分支；保存的 spec 被钉成 commit 后用它指明分支
      '@local/wechat-worklog': dsh-plugin
    backgroundCheckMs: 0           # 后台巡检间隔；0 关闭（默认，页面打开时会自动检查）
    backgroundCheckStartMs: 60000  # 开启后台巡检时，启动多久后首次巡检
```

## 已知限制

- 更新会改写依赖声明（钉 commit 模式），并短暂卸载该插件；重装会把 bundle 重新追加到 `dsh.profile.bundles` 末尾，可能改变配置优先级（宿主既有行为）。
- 并行更新只是让各行的进度互不阻塞；真正的 pnpm/卸载/安装仍由宿主的 profile 写锁排队执行，所以两个安装很少会同时跑，但它们会各自推进、各自回滚。
- 不能在更新前预检新版本与当前 DSH 的兼容性（目标 commit 的清单不联网读），改为装后校验 + 自动回滚。
- 需要本机有 `git`；只用 `git ls-remote` 读 ref，不 fetch 整个仓库、不调 GitHub API。
- 私有仓库按锁文件/探测结果改用本机 SSH key，并以「包名@git+ssh://…」安装：既避开 pnpm 11 在「仓库名 ≠ 包名 + commit」时把 fragment 混进 alias 的 `ERR_PNPM_INVALID_DEPENDENCY_NAME`，也不会卡在 HTTPS 凭据提示。
- 「只能走 SSH」是粘性的：一次探测/更新确认过之后记在 `state.json` 的 `transport`，之后检查和安装都直接先走 SSH，不再碰会要凭据的 HTTPS；GitHub 把私有仓库匿名访问报成 `Repository not found.` 时同样会回退到 SSH 试一次。
- 保存的 spec 是 commit 时，工具会用「已装 commit 对上哪个分支的尖端」反查跟踪分支；如果分支已经往前走、对不上，需要在 `trackedRefs` 里显式写分支（否则退回按远端 HEAD 判断）。
- 「那一行不消失」由宿主内存里的任务快照保证；宿主进程重启后，若某插件确实没装回来，行会消失（这是真实状态）。
- 设置页是唯一入口：关掉设置期间任务继续跑，但没有全局 toast；重开设置后从任务状态恢复进度。已完成任务的日志不会跨设置页保留；运行中任务的日志会保留，任务结束后再关闭/重开才会清掉。
- 日志清理是宿主路由新增的动作（`POST {action:"clearLogs"}`）：旧宿主没重启前这个请求会被拒绝并静默忽略，名称跳转不受影响。
- 宿主不提供重启服务，重启 DSH 只能由用户手动完成。
- 部分宿主错误码有本地化文案，未覆盖的错误直接显示宿主原文（多为中文）。
